# DeepSeek-V4.1-Flash MXFP4 (dsv41 img, 4x, DSpark k=5, Engram-on-disk) — reproducible recipe card

Generated by `sm121 publish` from the [sm121-launcher](https://git.kilork.org/sm121/sm121-launcher) recipe `dsv41-flash-4x` (engine: vllm, model: `deepseek-ai/DeepSeek-V4.1-Flash`).

**`recipe.toml` is the source of truth — its header comments document every non-obvious flag and the measured boot markers. Read it first.**

## What this is

DeepSeek-V4.1-Flash (MXFP4, **475 GB**, 256 layers + 2 Engram/disk-memory layers) served on
**4× NVIDIA DGX Spark (GB10, arm64, 128 GB unified memory)** — TP=4 over a 200 Gbps fabric,
DSpark/MTP speculative decoding (k=5), Engram on **per-node NVMe** (not NFS at runtime),
512K context, **thinking ON by default** (`{"thinking": true, "reasoning_effort": "max"}`,
overridable per request), served under the alias `deepseek-v4-flash`.

The image is a **clone-at-pin build** — everything is pinned and gated at build time:

| thing | pin |
|---|---|
| base image | `docker.io/vllm/vllm-openai@sha256:a551e053…c23f0` (digest) |
| vLLM tree | `vllm-project/vllm` `e47aa780bccf` / tree `8bf2b40345` (branch `dsv41-feat`, day-0 2026-09-08) |
| `_C_stable_libtorch` | rebuilt in-image for `sm_121a` (torch 2.12.0 / cu13.3) |
| FlashInfer | `07869c61ba58` (0.7.0rc1), JIT prewarmed (12 kernels, hard-gated) |
| Cutlass | `v4.7.1` (FI build input) |
| model | `deepseek-ai/DeepSeek-V4.1-Flash` @ `dba1be0a40aa45a94ad051997016db3960a90277` |

The 8 `*.py` files in this gist are the **post-build overlay patches** (tonyd2wild's
attention/engram/sparse-attn stack), applied with md5 gates; see `PROVENANCE.md` and
`mounts.txt` for the exact target files.

## Measured (4× DGX Spark, tool-eval-bench hardmode, seed 42, 88 scenarios)

| stack | score | d0 c1: pp / tg / TTFT (ms) |
|---|---|---|
| base (512K, thinking on) | 158/176 (90) | 1,387 / 39.9 / 1,886 |
| **+ b12x MoE** (overlay below) | **167/176 (95)** | 1,642 / 47.0 / 1,738 |

Decode: 71.5 tok/s counting (base) → **95.4 tok/s (b12x)**; 128K prefill 1.64 s (pp).
1M ctx was rejected in favour of 512K — the per-step sparse-indexer scoring cost
~35% of decode at 1M; 512K also halved the indexer prefill buffer (5.2 → 2.6 GiB).

## Live configuration: base + b12x (what we actually serve)

Our live lane is this image **plus** the b12x MoE overlay (MXFP4×MXFP8 kernels,
clamped SwiGLU — the numerics also shift borderline tool-eval scenarios in our
favour: 158/176 → **167/176**). It is one thin Docker layer on top of the built
image — no base rebuild:

```dockerfile
# Dockerfile.b12x — build on any node that has dsv41-flash:local
FROM dsv41-flash:local
RUN pip install --no-cache-dir b12x==1.3.0
ENV B12X_CACHE_DIR=/root/.cache/b12x
```

```bash
docker build -t dsv41-flash-b12x:local -f Dockerfile.b12x .
```

Then on **every rank**'s docker run add:

- engine flag: `--moe-backend b12x` (right after the model name in the args);
- a small persistent JIT cache dir (JIT-compiles ~1.4 MB on first boot, cached
  afterwards): `-v /home/<user>/sm121-cache/jit-121f/b12x:/root/.cache/b12x`.

Measured with the overlay (d0 c1, pp/tg/TTFT ms): 1,387 / 39.9 / 1,886 →
**1,642 / 47.0 / 1,738**; counting decode 71.5 → **95.4 tok/s**.

## Prerequisites

- 4× DGX Spark with a 200 Gbps (RoCE) fabric between them (100 Gb works, slightly slower NCCL);
- the model (475 GB) on a shared cache mounted identically on all nodes (NFS4 here), or
  500 GB free per node for local copies;
- ~50 GB image + per-node ~47 GB Engram copy (below);
- build on any arm64 GPU-less node (the build does no GPU work — stable-ext is
  file-validated, JIT is prewarmed at build time).

## Engram node-local setup (one-time per node, ~40 GB free per node)

Engram layers (1 and 14) hold 384 M rows of "disk memory" in 2 sparse shards
(`model-00047`/`00048.safetensors`). At serve time each TP rank reads **its row range**
(mislaid head buckets, not a /4 split — the ranges come from the first boot log line
`Engram layer N rows [start, end)`). Copy each rank's sparse shards to local NVMe so the
runtime never touches NFS:

```bash
# per node, after the first boot logged the ranges (tools/engram_local.py in the
# tonyd2wild repo, or the launcher's recipe comments):
#   e.g. rank0: layer1 [0, 96000564)  layer14 [0, 96003054)
# produces /var/tmp/engram-local/DeepSeek-V4.1-Flash/{model-0004x.safetensors, engram-local.json}
# then add to the docker run:  -v /var/tmp/engram-local/DeepSeek-V4.1-Flash:/engram-local:ro
#   and env:  DSV41_ENGRAM_LOCAL=1  DSV41_ENGRAM_DIR=/engram-local
```

Without it the engine reads Engram from the shared cache (works, but NFS-bound).

## Run

Cache the model on every node (see `recipe.toml` PREREQUISITES), edit `MASTER_ADDR`/fabric
env in `run.sh`, run on rank 0, then on each worker with `NODE_RANK`/`HEADLESS` set.
`recipe.toml` `[[extra_mounts]]` and built-in `before_serve` host scripts are launcher-side —
translate manually if needed. Cold boot (cold NFS): ~45 min to the readiness line (a second
per-expert weight pass is normal and expected); warm page cache: ~12 min.
